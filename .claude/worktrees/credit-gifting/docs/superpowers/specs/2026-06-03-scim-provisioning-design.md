# SCIM 2.0 Provisioning + Group Sync, per-org (Spec 3b) — Design

**Date:** 2026-06-03
**Status:** Approved — Entra-pragmatic SCIM 2.0 subset, fully real this pass. Follows Spec 3a (Entra SSO); reuses the `user_identities` correlation layer and the org's verified-domain guard. SCIM-driven role assignment is out of scope (members provision as `:member`).
**Nature:** Real build. Per-org SCIM 2.0 service provider (RFC 7643/7644) so an enterprise customer's IdP — Microsoft Entra ID specifically — can push user/group provisioning, updates, and deprovisioning into the org. This is the admin-driven **push** counterpart to Spec 3a's JIT **pull** provisioning.

## Why

Enterprise IT does not want to hand-manage who has access. They expect their identity provider to be the system of record: assign a user to the PerfectPaper app (or a group) in Entra, and that user is provisioned into the org; unassign or deactivate them in Entra, and access is revoked — with an audit trail. Spec 3a authenticates federated users at login; Spec 3b keeps the org's membership in continuous sync with the customer's directory. Together they close the enterprise identity-lifecycle loop.

## Locked decisions (brainstorming)

| Decision | Choice |
|---|---|
| Conformance scope | **Entra-pragmatic subset.** Exactly what the Entra SCIM client calls: `/Users` + `/Groups` CRUD + PATCH, filter by `userName`/`externalId`/`displayName` (`eq` only), cursor pagination, and the `/ServiceProviderConfig` + `/Schemas` + `/ResourceTypes` discovery endpoints. Spec-compliant for the resources we advertise; we do not build unused operators/resources. |
| Deprovisioning | **Soft-deactivate, keep audit trail.** `active:false` PATCH and DELETE both soft-deactivate: revoke sessions/API access immediately, strip group memberships + resource grants, mark the membership `:deactivated` — but RETAIN the user row, authored comments, and history. Reactivatable. No hard delete. |
| Group mapping | **Flat, SCIM-managed.** Each SCIM Group becomes a flat group directly under the org root (`kind: :group`, no parent), tagged `scim_managed` with its `externalId`; membership syncs into `group_memberships`. We do not infer hierarchy from Entra (it sends none); the manual `college→department→lab` tree coexists. |
| SCIM auth | **Dedicated per-org SCIM token.** A new `scim_tokens` concept: one token per org, generated by an admin, shown once, SHA-256-hashed at rest, constant-time-compared, rotatable/revocable. `/scim/v2` authenticates ONLY this token type and derives the org from it. Blast-radius isolation from the regular REST API. |
| Identity correlation | **`externalId` + email, domain-gated.** SCIM writes a `user_identities` row with `provider: "scim:#{org_id}"`, `uid: externalId`, reusing the Spec 3a correlation table. POST for an email/externalId already in the org **reconciles** (links + marks managed) instead of erroring. Every provisioned `userName` is enforced within the org's verified email domain. An SSO login (3a `resolve_sso_identity`) finds the pre-provisioned user → no duplicates. |
| Context boundary | **New `Scim` context (anti-corruption layer).** The only SCIM-aware module; keeps the protocol's quirks (URN schemas, PATCH grammar, filter parsing, error envelopes) out of `Organizations`/`Accounts`, which expose only generic, reusable lifecycle functions. |

## Architecture

### Context boundary — `PerfectPaper.Scim`
The single SCIM-aware module and the sole `Repo`/IO boundary for `scim_tokens`. It parses inbound SCIM JSON, validates through changesets (Law 4: changeset on every write even when it doesn't persist), translates to domain calls, and renders SCIM JSON + error envelopes. It calls `Accounts`, `Organizations`, and `Authz` through their **public APIs only** — never their `Repo` or submodules.

Submodules (flat-first per CLAUDE.md; promote only if a piece grows large):
- `lib/perfect_paper/scim.ex` — context API + `Repo` boundary + orchestration (provision / deactivate / reactivate / group-sync; owns the `externalId`↔resource mapping and reconciliation logic).
- `lib/perfect_paper/scim/token.ex` — `scim_tokens` schema + changeset; generation hashes the secret (the schema never stores plaintext).
- `lib/perfect_paper/scim/filter_parser.ex` — a lightweight parser for the three `eq` filters Entra sends (`userName`/`externalId`/`displayName`), case-insensitive on the attribute name, exact-match on the value. Returns a structured `{:eq, attr, value}` or `:no_match` for an unrecognized/empty filter. **It never raises and never produces an error response** — an unrecognized filter degrades to "no resource matches."
- `lib/perfect_paper/scim/patch_parser.ex` — resolves a SCIM PatchOp into a normalized list of operations, tolerating Entra's two deactivation shapes and both boolean encodings (see "Entra interop" below).
- `lib/perfect_paper/scim/user.ex` and `scim/group.ex` — `embedded_schema` validation of inbound payloads + SCIM resource rendering (incl. `meta`, `schemas`).

### Web layer
- `lib/perfect_paper_web/scim/*` controllers under `scope "/scim/v2"`: `UserController`, `GroupController`, and a `DiscoveryController` (`ServiceProviderConfig` / `ResourceTypes` / `Schemas`). Thin → `Scim` context.
- `PerfectPaperWeb.Plugs.ScimAuth` — extracts the `Authorization: Bearer` token, SHA-256-hashes it, `Plug.Crypto.secure_compare/2` against `scim_tokens.token_hash`, assigns `conn.assigns.scim_org` (the resolved org) and touches `last_used_at`. Missing/invalid → 401 SCIM error. A dedicated `:scim` pipeline (JSON, this plug, no browser CSRF/session).
- `PerfectPaperWeb.Scim.FallbackController` — renders the SCIM `Error` envelope for `{:error, _}` tuples.

### Data model (migrations)
- **`scim_tokens`** — `id` binary_id, `organization_id` binary_id (UNIQUE — one active token per org this pass; rotation replaces the row), `token_hash` :string (SHA-256 hex; **verify-only credential, so hashing is correct and stricter than reversible at-rest encryption**), `created_by` binary_id (user), `last_used_at` :utc_datetime (nullable), timestamps.
- **`memberships`** += `status` `Ecto.Enum [:active, :deactivated]` (default `:active`), `deactivated_at` :utc_datetime (nullable). Backfill existing rows to `:active`.
- **`groups`** += `scim_managed` :boolean (default `false`), `scim_external_id` :string (nullable; UNIQUE per `organization_id` via a partial/compound index). The context maintains these; never cast from arbitrary user input.
- **`users`** += `deactivated_at` :utc_datetime (nullable). Set when a SCIM-managed user is deactivated and has no other active membership; `user_auth.ex` and the token-refresh path block a deactivated user from logging in.
- **`user_identities`** — reused unchanged except `validate_provider/1` gains the `"scim:"` prefix. SCIM writes `provider: "scim:#{org_id}"`, `uid: externalId`.

### Domain API additions (generic, reusable — NOT SCIM-aware)
Added to existing contexts so SCIM (and any future admin UI) can drive the lifecycle; named for the business step, free of SCIM vocabulary:
- `Organizations.deactivate_membership(org, user_id)` — `Ecto.Multi`: set membership `:deactivated` + `deactivated_at`, delete the user's `group_memberships` in this org, revoke the user's `resource_grants` scoped to this org. Returns the membership.
- `Organizations.reactivate_membership(org, user_id)` — reverse the status; group/grant re-add is the IdP's job on the next sync (we do not resurrect stripped memberships).
- `Organizations.remove_member(org, user_id)` — soft path; delegates to `deactivate_membership` (no hard delete this pass).
- `Organizations.set_group_members(group, user_ids)` — **idempotent**: reconcile `group_memberships` to exactly `user_ids` (add missing, remove absent, no error if already-present). The cornerstone of the Entra group-PATCH retry safety below.
- `Organizations.update_group(group, attrs)` and `get_group_by_scim_id(org, external_id)`.
- `Accounts.deactivate_user(user)` / `reactivate_user(user)` — set/clear `deactivated_at` and (on deactivate) `Repo.delete_all` the user's `UserToken`s so active sessions die immediately.
- Identity helpers so `Scim` can resolve-or-provision: get user by `(provider, uid)`, get by email within the org's verified domain, and provision a new passwordless user with the `scim:#{org_id}` identity written atomically — reusing the Spec 3a `user_identities` path so a later SSO login resolves to the same `user_id`.

### Endpoints (`/scim/v2`, Entra subset)
- `GET /ServiceProviderConfig` — advertises `patch: {supported: true}`, `filter: {supported: true, maxResults: 100}`, `bulk/sort/etag: {supported: false}`, `authenticationSchemes: [oauthbearertoken]`.
- `GET /ResourceTypes`, `GET /Schemas` — static User, Group, and EnterpriseUser schema documents.
- **Users**
  - `GET /Users?filter=…&startIndex=&count=` → `ListResponse`. **No match → HTTP 200 with `totalResults: 0`, `itemsPerPage: 0`, empty `Resources` — never 4xx/5xx** (see Entra trap #1).
  - `GET /Users/:id` → User resource or 404 SCIM error.
  - `POST /Users` → provision; if `externalId` or email already exists in the org, **reconcile** (link the identity + mark managed) and return 200/201 rather than 409.
  - `PATCH /Users/:id` → PatchParser; `active:false` → soft-deactivate; attribute updates (name/displayName).
  - `PUT /Users/:id` → full replace (supported even though Entra prefers PATCH).
  - `DELETE /Users/:id` → soft-deactivate → 204.
- **Groups**
  - `GET /Groups?filter=displayName eq "…"` (and `externalId eq`) → `ListResponse`, same empty-200 rule.
  - `GET /Groups/:id` → Group resource or 404.
  - `POST /Groups` → create a flat `scim_managed` group (Entra creates it empty, then PATCHes members).
  - `PATCH /Groups/:id` → add/remove/replace members + rename; idempotent (see trap #2).
  - `PUT /Groups/:id`, `DELETE /Groups/:id` (delete → remove the SCIM-managed group + its memberships).

### Entra interop (MANDATORY — first-try-success traps)
1. **Test-Connection / pre-create query never errors.** Entra validates the integration by querying before it creates — `GET /Users?filter=userName eq "<random-or-empty>"`, `GET /Groups?filter=displayName eq "…"`, `externalId eq "…"`. A no-match (or an unparseable/empty filter) MUST return `200 OK` with a valid empty `ListResponse` (`totalResults: 0`). Returning 400/404/500 here blocks the entire integration setup. `FilterParser` returning `:no_match` routes to the empty-list response, not an error.
2. **Group-PATCH retry-loop avoidance.** Entra creates a group empty then issues sequential `PATCH …/Groups/:id` `add members` ops, and is known to **repeat the same PATCH 3–5×** even after a 200 if the response doesn't satisfy its confirmation validator. Defenses: (a) `Organizations.set_group_members/2` is strictly **idempotent** — adding an already-present member is a success, not an error; (b) the `PATCH /Groups/:id` controller returns **`204 No Content`** (Entra-supported and simplest) on success — avoiding payload-shape disputes that trigger the retry storm. (If a body is ever needed, return the full updated Group with the current `members` array.)
3. **PATCH shape tolerance.** `active:false` arrives as either `{op:"replace", path:"active", value:"false"}` (path-targeted) or `{op:"replace", value:{active:false}}` (value-targeted), and the boolean may be the string `"false"` or the literal `false`. `PatchParser` normalizes all four into one canonical operation via pattern matching.

### Error handling
A `Scim.FallbackController` renders the SCIM `Error` envelope (`schemas: ["urn:ietf:params:scim:api:messages:2.0:Error"]`, `status`, optional `scimType`, `detail`) and maps: 401 (bad/missing token), 404 (`Users/:id`/`Groups/:id` not found), 400 `invalidSyntax` (genuinely malformed PATCH body — distinct from an unrecognized *filter*, which is a 200 empty list), 400 `invalidValue` (e.g. a `userName` outside the verified domain), 400 `mutability` (attempt to deactivate the sole org owner — see below). The no-match **query** is a success, not an error.

**Owner-deactivation block.** SCIM must never orphan an org by deactivating its sole `:owner`. Rather than silently succeed (which would leave Entra believing the user is deprovisioned while they remain active), `deactivate_membership` returns `{:error, :sole_owner}`, which the FallbackController renders as a **`400` with `scimType: "mutability"`** and `detail: "Cannot deactivate the sole organization owner. Please transfer ownership in PerfectPaper before deprovisioning this user."` — surfacing the block in the customer's Entra provisioning logs so an admin transfers ownership first.

### Events & audit (SOC 2 CC6.2 / CC6.3)
Post-commit `Events.emit/2` (never inside the Multi): `:"member.provisioned"`, `:"member.deactivated"`, `:"member.reactivated"`, `:"group.synced"` — each `organization_id`-scoped so they fan out to webhooks (Spec 8) + PubSub. The `deactivated_at` timestamps plus these events constitute the deprovisioning audit evidence. New event types added to `Events.Event`.

### Security
- The SCIM token authorizes **only** `/scim/v2` (separate plug + dedicated token type) — a leaked SCIM token cannot call the regular REST API, and an API key cannot call SCIM.
- Token hashed at rest (SHA-256), constant-time compared, shown once at generation, rotatable/revocable. No plaintext credential at rest (SOC 2 CC6.1/CC6.7).
- Every provisioned `userName`/email is enforced **within the org's verified email domain** (reuse the Spec 3a guard) — an over-broad SCIM token can't provision arbitrary external accounts into the org.
- Deactivation revokes all of the user's session/API tokens immediately, so a deprovisioned user cannot continue an in-flight session.
- `scim_managed`/`scim_external_id`/membership `status` are context-maintained, never cast from request bodies.

### Management UI
A "Directory provisioning (SCIM)" panel on the org-admin SSO page (`SsoLive` or a sibling LiveView, org-admin gated): a **Generate token** action (the plaintext is shown exactly once, then only the hash persists), the `/scim/v2` base URL to paste into Entra, the last-sync timestamp (`last_used_at`), and **Rotate** / **Revoke** actions. Discrete test ids; paper theme; secrets shown only as set/not-set after generation; no emoji; no `raw`.

## Testing

- **`FilterParser`** (unit): `userName eq`, `externalId eq`, `displayName eq`; case-insensitive attribute; quoted value extraction; empty/garbage/`and`-compound filter → `:no_match` (never raises).
- **`PatchParser`** (unit): path-targeted vs value-targeted `active:false`; stringified `"false"` vs literal `false`; `add`/`remove`/`replace` members ops; malformed body → an error the controller maps to 400 `invalidSyntax`.
- **`Scim` context**: provision new user (writes `scim:#{org_id}` identity, membership, within-domain enforced); provision an email already in the org → reconciles, no duplicate; provision an email that already has a 3a SSO identity → links to the same `user_id`; reject a `userName` outside the verified domain; deactivate (membership `:deactivated`, `UserToken`s gone, group memberships stripped, event emitted); reactivate; group create → `set_group_members` (idempotent: re-adding is a no-op success) → rename → delete.
- **Controllers**: Test-Connection simulation — `GET /Users?filter=userName eq "<random>"` and `GET /Groups?filter=displayName eq "X"` with no match → **200 empty `ListResponse`**; `POST /Groups` empty then `PATCH add members` repeated twice → second call still 204, membership unchanged (retry-loop safety); auth (no/wrong token → 401, `secure_compare` path); `GET /Users/:id` missing → 404 SCIM error envelope; `ServiceProviderConfig`/`Schemas`/`ResourceTypes` shape; pagination (`startIndex`/`count`); `DELETE /Users/:id` → 204 + soft-deactivated.
- **Correlation end-to-end**: SCIM-provision a user, then run the Spec 3a SSO `resolve_sso_identity` for the same email/IdP → resolves to the **same** `user_id` (no second account).
- **Deactivation auth**: a deactivated user's existing session token no longer authenticates (`user_auth` blocks on `deactivated_at`).

## Out of scope (this pass — TODO / later)

- Bulk operations (`/Bulk`), sorting, ETags/versioning, and the full filter grammar (`ne/co/sw/ew/gt/ge/lt/le/pr`, `and/or/not`) — only `eq` on the three queried attributes.
- More than one SCIM token per org, or more than one verified domain per org.
- SCIM-driven **role** assignment / role mapping — provisioned members get `:member`; role changes remain manual (`Organizations`). (Group-to-role mapping is a candidate follow-up.)
- SCIM token encryption-at-rest is N/A (hashed, not stored); the shared `TODO(sso)` credential-encryption work covers the *reversible* SSO secrets, not this.
- Inbound de-dup of repeated provisioning beyond idempotent upserts; no SCIM `meta.version`/concurrency control.

## Open questions

1. **Group-to-role mapping** — should membership of a specific SCIM group eventually map to an org role (e.g. an "Admins" group → `:admin`)? Default: out of scope here; members provision as `:member`, note as a follow-up.
2. **`maxResults` for `filter`/pagination** — resolved to 100 (Entra-friendly) advertised, with the `count` request param capped at 200. Confirm during planning if a different cap is preferred.
3. **Deactivating the org owner** — RESOLVED: SCIM-deactivating the sole org `:owner` is refused with a **`400` SCIM error, `scimType: "mutability"`** (not a silent success), so the block appears in Entra's provisioning logs and the admin transfers ownership before deprovisioning. See "Owner-deactivation block" under Error handling.
